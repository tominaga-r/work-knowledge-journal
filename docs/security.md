# セキュリティ設計と制限

## 1. 前提と保護対象

本アプリはWindows向けのローカルデスクトップアプリであり、外部公開WebサービスやクラウドDBは利用しない。主な保護対象は、端末に保存される業務メモ、バックアップファイル、復元時のデータ整合性である。

**顧客氏名・連絡先・購入履歴・社外秘情報・非公開の商品情報などは保存対象外とする。** 匿名化・一般化した情報を利用者自身が判断して登録する前提であり、アプリが機密情報を完全に自動検出・遮断するものではない。

## 2. 実施している対策

| 項目               | 対応                                                                               | 制限・補足                                       |
| ------------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------ |
| 入力検証           | Zodにより必須項目・文字数・選択値を検証。Repository側でも保存前の検証を行う設計    | 入力内容の真偽や機密性までは保証しない           |
| SQL                | DB操作をRepositoryに集約し、入力値はSQLパラメータとして扱う設計                    |                                                  |
| HTML表示           | Reactの通常の文字列レンダリングを使用。動的な生HTML挿入に依存しない設計            | CSPと併用する防御の一層                          |
| Tauri権限          | 基本機能とSQLプラグインに必要な範囲へcapabilityを制限                              | 権限を絞るだけで全脅威を排除できない             |
| CSP                | `default-src 'self'`を基本とする制限付きポリシーを設定                             | 開発時・配布時の設定変更に注意                   |
| バックアップ復元   | JSON形式、アプリ識別、バージョン、必要テーブル・行データ型の検証、復元前の件数表示 | 値の業務的妥当性や復元の完全な原子性は保証しない |
| 暗号化バックアップ | Web Crypto APIを利用したAES-GCM。PBKDF2/SHA-256でパスワードから鍵導出              | 保護対象は暗号化バックアップファイルのみ         |
| 依存関係           | npm audit / RustSecによる依存監査、Dependabot、CodeQL、CIを利用                    | 監査の0件は将来の脆弱性がないことを意味しない    |

## 3. 暗号化の範囲

### 通常バックアップ

JSONファイルは**暗号化されない**。保存先や共有先から本文が読めるため、取り扱いに注意する。

### 暗号化バックアップ

利用者のパスワードから鍵を導出し、JSONをAES-GCMで暗号化する。パスワードの誤りや暗号文の改ざんを検出する仕組みを利用する。一方、パスワードを忘れた場合の復号手段は用意していない。

### ローカルDB

端末内SQLiteファイル自体は暗号化していない。端末のアクセス権を持つ者によるDBファイルの直接閲覧・コピーに対して、アプリのみで完全に保護することはできない。利用端末側のアクセス制御と、保存内容の選別が必要である。

## 4. 復元時の安全性と限界

- 不正な形式、別アプリのJSON、必須データ不足、誤パスワードなどを復元前に検出する。
- 現在のDBと復元対象の件数を比較してから操作する。
- 復元は既存データへ影響するため、テストデータで確認し、必要に応じ事前にバックアップを作成する。
- **復元操作全体は完全なトランザクションで保護されていない。** 電源断・ストレージ障害・途中エラー時に、元のデータへ自動で戻ることを保証できない。改善候補としてRust側でのトランザクション制御を検討する。

## 5. 依存監査結果の読み方

- `npm audit` はJavaScript/npm側の依存を確認する。
- `cargo audit` はRust側の`Cargo.lock`を検査し、Windows配布版には含まれない他OS向けの依存や、未使用の機能に由来する警告も表示し得る。
- Rust側で過去に検出された`rsa`、`glib`、`proc-macro-error`について、Windows x64のnormal/build依存グラフでは`cargo tree -i`が対象を表示しないことを確認した。ただし、残存する警告については、Windows向け依存グラフへの影響と区別して管理する。依存構成の変更後には再評価が必要。
- 監査結果は実行日と依存バージョンによって変わる。ここに書いた内容を永続的な「脆弱性ゼロ」宣言として扱わない。

## 6. 配布・運用に関する注意

- 機密データを含まないテスト用記録のみを、リポジトリ・スクリーンショット・配布資料に使用する。
- 本番のバックアップ、パスワード、秘密鍵、個人情報をGitへコミットしない。
- インストーラーの生成成功と、コード署名・配布時の信頼性確認は別問題である。現時点ではインストーラーのコード署名には対応していない。
- 依存の更新後は自動テストに加え、Windowsアプリの起動・データ保存・バックアップと復元を実機で確認する。

## 7. 未実装・今後の検討

- 復元操作の一括トランザクション化と障害時の復旧保証
- 大規模データでの性能・復元耐障害性評価
- コード署名を含む配布運用の整備
