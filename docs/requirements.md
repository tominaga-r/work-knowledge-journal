# 要件とスコープ

## 1. 目的

接客・販売・事務などの業務で得た知識や問い合わせ時の気づきを、散在したメモのままにせず、あとから検索・参照・振り返りに使える状態で整理する。単に保存するだけでなく、問い合わせ対応とナレッジを結び付けることを目指す。

## 2. 想定利用者・利用環境

- 主な利用者：個人で業務知識や対応メモを蓄積する人
- 想定場面：業務知識の整理、問い合わせ対応の記録、定期的な振り返り
- 配布対象：Windows x64 のローカルデスクトップ環境
- データ管理：端末内のSQLite。クラウドへの同期や共有は前提としない

**想定利用者は実運用ユーザー調査で確定したものではなく、設計上の対象です。**

## 4. 非機能上の考慮

- **操作性**：専門用語を必要以上に表示しない。取り込み前・復元前に利用者が内容や影響を確認できること。
- **データ保全**：バックアップと復元前の形式検証を用意すること。ただし、復元処理全体のトランザクション保証は現時点では設けていない。
- **入力検証**：Zodで必要項目や上限を検証し、保存側でも検証すること。
- **セキュリティ**：Tauri権限の絞り込み、CSP、SQLバインド、バックアップ暗号化、依存監査を実施すること。
- **保守性**：画面・Repository・スキーマ・共通処理を機能別に分け、静的解析と単体テストを実行可能にすること。

性能、アクセシビリティ、可用性、バックアップ耐障害性について、測定に基づく数値保証は設定していない。

## 5. 明示的な対象外

- クラウド同期、複数ユーザーでの同時編集、共有ワークフロー
- ログインや権限ロールを伴うユーザー管理
- 機密・個人情報の保管を目的とした利用
- 端末上のSQLiteデータベース全体の暗号化
- Windows以外の配布版の保証

## 6. 受け入れ観点

- インストーラーから起動でき、アプリを再起動しても登録データが残る。
- ナレッジと問い合わせメモで作成・編集・削除と一覧からの参照ができる。
- 分類、共通タグ、検索・絞り込み、お気に入り、関連ナレッジが想定どおり動作する。
- `.txt` / `.md` の取り込み時、保存前に内容を確認できる。
- 通常・暗号化バックアップを作成し、検証・プレビューを経てテストデータを復元できる。
- 不正なJSON、形式違い、誤パスワードを適切なエラーとして扱う。

上記は**リリース判定に用いるチェック項目**であり、すべての環境・ケースで完了したという主張ではない。記録方法は [テスト・検証](testing.md) を参照。
